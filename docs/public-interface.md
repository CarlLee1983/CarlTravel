# 公開介面與無障礙驗證

## 路由與導覽

| 路由 | 讀者用途 | 正式 sitemap |
| --- | --- | --- |
| `/` | 網站介紹、資訊分類、審閱流程與景點列表第 1 頁；帶查詢參數（`/?query=…&county=…&page=N`）時由前端以列表 JSON 渲染同一份列表 | 收錄 `/`，不收錄帶參數的網址 |
| `/page/<N>/` | 景點列表第 2 頁以後（N ≥ 2，每頁 24 筆，無條件、靜態）；只有頁首、搜尋、範圍文字、列表與分頁器，沒有首頁介紹、插畫與資訊分類說明。不產生 `/page/1/`（第 1 頁就是 `/`） | 不收錄 |
| `/spots/<id>/` | 景點閱讀、出發前確認、摺疊章節、出處與地圖連結 | 只收錄 `content/spots/` 的正式景點 |
| `/about/` | 資訊分類、「看到『未知』時」用語說明、使用前確認、授權範圍與署名方式 | 收錄 |
| 無效網址／`404.html` | 404 狀態、搜尋表單（GET 送到 `/?query=`）、回景點列表與關於頁 | 不收錄，並標示 noindex |

共用頁首連向景點列表（固定連到 `/`，景點頁帶 `aria-current="true"`，列表頁含 `/page/<N>/` 帶 `"page"`）與關於頁，頁尾署名為純文字，頁尾連結列（每個連結至少 44px 高）連向「使用前確認」`/about/#disclaimer` 與「內容授權」`/about/#license`；所有頁面的 head 有 CC BY-NC 4.0 `rel="license"`。景點頁另有位於來源區之後的短版使用前確認。開放資料顯名沿用景點出處欄位，不混入本站內容授權。

## 版面與行為

首頁以精簡標題與搜尋作入口；桌面保留小幅情境插畫，700px 以下省略插畫，讓搜尋與首筆景點優先出現。搜尋在列表上方，縣市、類型、環境與年齡帶放在原生可展開的「篩選條件」，初始收合。選項只提供至少一個景點使用的值；當全部景點的年齡都未知時，隱藏沒有區分作用的年齡篩選。條件以交集套用，清除條件會清空搜尋與全部選項；已選條件也可逐項移除。

列表每頁 24 筆。列表上方有一行範圍文字（例如「第 25–48 筆，共 62 筆」），是 `role="status"`、`aria-live="polite"` 的唯一筆數播報處，標題與其他地方不再重複筆數；沒有結果時寫「沒有符合條件的景點」。列表開頭有「跳到分頁」略過連結，列表底部是分頁器（`<nav aria-label="分頁">`）：手機（700px 以下）是「上一頁、目前頁／總頁數、下一頁」，桌面另顯示第一頁、最後一頁與目前頁前後各 2 個頁碼，每個控制項都是真的連結（可用新分頁開啟），不提供輸入頁碼跳頁。無條件時換頁是一般導覽（`/`、`/page/<N>/`），新頁面載入後把畫面捲到列表開頭並讓範圍文字取得焦點；帶條件時在同一份文件內換頁（`pushState`）並做同樣的捲動與焦點。第 2 頁以後的列表標題仍是「景點列表」，另有只給輔助科技的 `<h1>`「景點列表 第 N 頁」。沒有 JavaScript 時搜尋與篩選控制項完全不顯示（`@media (scripting: none)` 隱藏表單，JavaScript 啟動後才可用），原位只留一行「搜尋與篩選需要 JavaScript」，全部景點仍可用 `/` 與 `/page/<N>/` 翻完。

列表卡片採「已知才列」版型，內容由 `src/content/list-card.ts` 的 `cardView(entry)` 從列表資料（`ListEntry`）產生，靜態頁與日後的瀏覽器端渲染共用。由上而下是：全寬名稱、「縣市 行政區 · 類型 · 環境」一行、營運狀態標籤位（只在有結構化狀態時顯示，目前沒有資料，不從摘要推定）、摘要。有已驗證插畫時在摘要左邊放 72×48 縮圖（來源為 336×224 的 3:2 縮圖，預留寬高、延遲載入及非同步解碼，其他比例置中裁切，不加白邊，保留描述圖片內容的替代文字）；沒有插畫時是純文字版面，不留空框或色塊。已知的年齡與五項親子條件做成標籤（例如「推車友善：有」），否定的用外框樣式；未知不逐項列出，收成一行：部分已知寫「另有 N 項親子條件未知、年齡未標示 · 查證 日期」（年齡已知則省略「年齡未標示」），全部未知寫「親子條件與年齡尚未整理，未知不代表沒有」且不顯示查證日期，全部已知則只寫「親子條件查證 日期」。未知不當作沒有，查證日期不當作有效期限，也不從摘要推定營運狀態或完整性評分。整張卡片只有標題一個連結，以延伸點擊區覆蓋整張卡片，每張只佔一個 Tab 停點，焦點框畫在整張卡片上；內部連結不使用「↗」。已選條件標籤是至少 44px 高、15px 字級的圓角外框按鈕，以全域樣式套用到動態產生的按鈕。沒有改動景點資料模型或正式內容。

資訊分類說明放在列表之後。無結果時提供「重新瀏覽全部景點」按鈕，重設同一份表單並把焦點放回搜尋框；搜尋中透過文字及 `aria-busy` 表示尚未完成，保留可瀏覽的篩選結果。失敗時清楚說明文字搜尋無法使用，仍可調整條件或清除搜尋恢復瀏覽。

全站內容在寬螢幕收束至約 1360px，導覽以淡藍底標示目前頁面；共用色彩與字型 tokens，閱讀區採白底、深藍字，以淡藍及淡薰衣草紫輔助資訊分區；標題優先使用系統圓體並回退到系統黑體，內文優先使用本機繁體中文黑體，主按鈕採全圓角。品牌名稱只保留頁首的小字，頁尾以「台灣親子出遊筆記」收尾。不載入外部字型，不新增正式景點或虛構推薦。進入畫面的說明與列表有一次性短距離位移，文字與控制項保持完整對比；不支援腳本時內容照常可讀，減少動態偏好停用位移。

沒有文字查詢時，列表沿用縣市列舉順序（`src/content/counties.ts`，內容載入器共用）由北到南，同縣市依名稱排序（名稱相同再依 id）；有文字查詢時依 Pagefind 的相關度排序，排序由 `src/content/list-query.ts` 負責。景點頁單欄（最寬 760px），文案邏輯在 `src/content/spot-page.ts`（純函式，`tests/spot-page.test.ts` 直接驗證）。由上而下是：返回列表連結、名稱、「縣市 行政區 · 類型 · 環境」一行、摘要、「出發前確認」卡、地址與地圖、章節摺疊列；390px 下名稱與卡片都在第一屏內。

「出發前確認」卡依序列出營運狀態、開放時間、費用、資訊衝突（有衝突才出現）、親子條件（「已知 N／5 項」或「尚未整理（未知不代表沒有）」）與建議年齡。每列是至少 48px 高的連結，連到對應章節。營運狀態沒有結構化資料時寫「未記錄異動，出發前請看官方公告」，不從摘要推定；營運狀態有值與資訊衝突兩列用深色底強調。結構化營運狀態的欄位尚未存在，頁面目前一律傳入「無」；欄位到位後，休園狀態會把地圖按鈕降為一行文字「目前休園，仍要查看位置」。沒有費用資料時，卡片與章節都寫「尚未整理，未列出不代表免費」。

章節是原生 `<details>`，摺疊列本身就是目錄，沒有另外的目錄或側欄。每列摘要寫出章節名稱與一句提要（例如「已知 2／5 項」「有衝突 · 費用尚未整理」），預設只展開親子清單；設施與「跟孩子一起看」沒有資料時，列成不能展開的「尚未整理」，不省略。親子清單只逐項列出已知項目與建議年齡，未知收成一列「未知 N 項：…，未知不代表沒有，可向〈官方機關〉確認」，全部未知時只留一段說明與確認管道；否定一律寫「沒有」。官方章節標籤合成「官方資訊 · 查證 日期」，超過一年加「查證已逾一年，請再確認」。從卡片的列或網址錨點進入時，`src/browser/spot-sections.ts` 展開目標章節並把焦點放到摘要上；沒有 JavaScript 時摺疊列仍可手動展開，卡片連結只跳到章節。離開本站的連結（地圖、出處、來源）帶可見的「↗」與報讀文字「（外部網站）」，在同一分頁開啟；內部連結不加。「使用前確認」短版區塊（`#spot-disclaimer`）仍在最後。頁面本身不以裁切溢出的方式掩蓋排版問題。關於頁提供三個章節入口並收窄長文行寬；404 沿用核准插畫，提供回索引及關於頁的連結。

官方資訊、原作者心得與 Agent 建議使用文字標籤；未知、官方未公布、衝突、過期、原文無法讀取與設施狀態均保留可讀文字。顏色只輔助辨識。地圖是具名文字外連，不嵌入地圖。搜尋使用少量前端 JavaScript 與建置時產生的 Pagefind 索引；不載入外部字型。景點內頁的已驗證 AI 情境插畫附替代文字及可見說明「AI 生成情境插畫，非實際展區」。

## 網站插畫的公開邊界

`public/illustrations/family-outing.png` 為 2026-10-15 A 定稿核准的 AI 生成親子出遊情境插畫，不代表特定景點或實地照片。圖檔保留透明背景與尺寸屬性，首頁與 404 提供替代文字。共用 head 加入路徑圖案的內嵌 SVG favicon、主題色與分享標題／描述／插畫 metadata，沒有新增外部資產請求或套件。

`scripts/site-assets.ts` 固定這一個相對路徑與 SHA-256，公開資產和正式輸出檢查共用同一份規則。替換圖檔需先視覺審閱，再更新雜湊；改名、額外圖片、符號連結仍拒絕。景點插畫另由正式 YAML 宣告的雜湊綁定，輸出只接受對應 `/spot-illustrations/<id>.png` 的精確 PNG 位元組；一般公開資產白名單仍嚴格限定。撤回網站共用插畫時一併移除首頁引用、圖檔與白名單項目。

## 驗證入口與範圍

- `pnpm check`：Astro 與 TypeScript 型別。
- `node --experimental-strip-types --test tests/content.test.ts tests/output.test.ts`：縣市／同縣市排序、正式輸出頁面、sitemap 白名單與 fixture 隔離。以暫存內容測正式景點的收錄與漏列；不寫入正式景點目錄。
- `pnpm build:fixture && pnpm exec playwright test e2e/site-pages.spec.ts`：站內導覽、404 回應、授權與免責連結、手機鍵盤章節跳轉、桌面／手機首頁布局、fixture sitemap XML。
- 列表入口另在 **390、1024、1200、1366px** 驗證精簡標題、桌面插畫及搜尋區不重疊；手機可直接操作搜尋，進階條件收合且可用鍵盤展開。減少動態偏好下不播放動畫。
- 同一份瀏覽器測試對首頁、`/page/2/`、一個帶條件的網址（`/?setting=戶外&page=2`）、最小景點、完整景點、關於頁、404，分別在 **360、390、430、1366、1920px** 執行 axe 與頁面水平溢出檢查。`e2e/paging.spec.ts` 驗證分頁：用 `/` 與 `/page/N/` 翻完 62 筆、第 2 頁以後沒有首頁介紹、分頁器兩種版本、略過連結、帶條件的換頁（網址、瀏覽紀錄、焦點）、改條件回第 1 頁、上一頁還原、頁碼修正、在 `/page/N/` 套用篩選導向 `/?…`、無條件頁面不下載列表 JSON，以及無 JavaScript 的翻頁與帶參數進站；其中標示 `@smoke` 的案例也在 WebKit 執行。完整景點測試另保留三種資訊、所有狀態、出處與開放資料顯名的內容驗證。
- `pnpm verify`：完整整合關卡，最後重新建置正式內容並檢查輸出。沒有直接部署討論原型或 fixture 的步驟。

自動無障礙檢查的範圍為 Chromium／axe，搭配鍵盤操作與桌面、手機截圖人工檢視；不宣稱涵蓋所有瀏覽器或螢幕閱讀器。真實來源、私人草稿索引隔離與正式部署驗收由後續票交付。

## 搜尋索引與模式

`src/content/search.ts` 將既有 `ageRange` 換算為相交的 0–2、3–6、7–12、13 歲以上年齡帶；unknown 只標示年齡未標示。列表頁直接從同一批載入的景點產生篩選的可選值，沒有另一份手工維護的景點資料；卡片本身不再帶篩選屬性，篩選與分頁交給列表查詢模組。

### 列表查詢模組與兩套網址

`src/content/list-query.ts` 的 `queryList(entries, conditions)` 是純函式（不碰 DOM 與網路，建置時的靜態分頁與瀏覽器端共用）：輸入解碼後的列表資料與條件（`hits` 文字命中的 id，依相關度排序，`null` 表示沒有文字條件；`county`、`kind`、`setting`、`age`；網址上的原始 `page`），輸出正規化後的條件、該頁的 24 筆、範圍 `{from, to, total}`、總頁數與 `needsUrlReplace`。資料裡沒有的條件值被忽略；頁碼超過最後一頁改成最後一頁，不是正整數視為第 1 頁，明寫的 `page=1` 也算不正規，這些情況 `needsUrlReplace` 為 true，呼叫端用 `replaceState` 修正網址。文字命中與其他四個條件取交集。`src/content/list-html.ts` 以字串產生卡片、範圍文字與分頁器，靜態頁（`set:html`）與瀏覽器端共用，所以兩邊的標記完全相同；`src/content/list-url.ts` 定義狀態與網址的對應。

網址分兩套，理由與取捨見 [ADR 0003](adr/0003-list-static-pages-and-query-urls.md)：沒有任何條件時第 1 頁是 `/`、第 N 頁是預先產生的 `/page/N/`（`src/pages/page/[page].astro`，不進 sitemap）；有任何條件時留在 `/`，用 `query`、`county`、`kind`、`setting`、`age`、`page` 參數，由瀏覽器端依列表 JSON 渲染。在 `/page/N/` 套用條件時導向 `/?…`；只有 `page` 參數而沒有條件的 `/?page=N` 導向 `/page/N/`。換頁用 `pushState`，改條件與修正網址用 `replaceState`，改任何條件都回到第 1 頁。

列表 JSON（`/spot-list/<hash>.json`）的載入時機：無條件的 `/` 與 `/page/<N>/` 不下載；第一次聚焦搜尋框或打開篩選區時才抓；帶條件的網址一進站就抓，抓到之前保留靜態第 1 頁並把範圍文字改成「載入中」，載入失敗則保留靜態第 1 頁並說明。不另做閒置時的預先下載，否則無條件頁面就會下載整份資料。

Astro 完成靜態頁面後，`scripts/search-index.ts` 只讀取當前模式載入器列出的景點 HTML，並透過 Pagefind 的 Node API 逐筆建立索引。輸出位於該模式的 `pagefind/` 目錄，正式與 fixture 分別在 `dist/` 與 `dist-fixture/`。不爬整個網站；零景點時產生空索引，不會退回收錄首頁、關於頁或 404。

索引根限制為景點頁的 `data-pagefind-body` 元素（章節收合與否不影響，e2e 以實際查詢驗證收合中的內容可被搜尋）：名稱（權重 10，最高）、縣市行政區、摘要、心得轉述、Agent 建議與跟孩子一起看的事實／活動。日期、地址、設施清單、官方數值、出處連結、引文與周邊安排均在白名單之外。標題 metadata 只取景點名稱。具體依據為 [Pagefind 索引設定](https://pagefind.app/docs/indexing/)、[Node API](https://pagefind.app/docs/node-api/)與[文字權重](https://pagefind.app/docs/weighting/)。

瀏覽器按需載入 Pagefind 索引，把命中的景點 id（依相關度）交給列表查詢模組與其他條件取交集，用結果重畫當頁的 24 張卡片，有文字查詢時依相關度排序。輸入採短暫延遲並支援中文組字；新查詢與清除會使舊回應失效。索引載入失敗時明示搜尋不可用，保留符合篩選的可瀏覽列表；未啟用 JavaScript 時保留全部景點並說明互動功能需要 JavaScript。

搜尋與條件以 `query`、`county`、`kind`、`setting`、`age`、`page` 網址參數保存。條件值依列表資料驗證，未知值忽略；其餘網址參數及錨點保留。修改條件以 `history.replaceState` 更新同一筆瀏覽紀錄並回到第 1 頁，避免每次輸入都增加上一頁步驟；換頁以 `history.pushState` 新增一筆，上一頁／下一頁從網址還原條件與頁碼。載入、重新整理及瀏覽歷史切換時恢復條件，非同步搜尋仍以最新請求為準。

從列表開啟景點時，捲動位置、連結焦點及篩選區開合狀態保存在該筆瀏覽紀錄，返回時待搜尋結果確定後恢復；沒有使用 cookie、跨頁追蹤或裝置共用儲存。網址可分享條件，捲動位置不隨網址分享。詳細頁上的返回入口仍開啟列表起點；瀏覽器上一頁用於回到原清單。無 JavaScript 時搜尋與篩選不輸出控制項、只留一行說明，帶參數的網址顯示未篩選的第 1 頁。開發預覽（`pnpm dev`）的靜態分頁含本機草稿，帶條件的前端渲染只有列表 JSON 的正式景點。

完整搜尋以 `pnpm build:fixture && pnpm preview:fixture` 檢視。`pnpm dev:fixture` 提供即時頁面與本機篩選，但不產生 Pagefind 索引；輸入搜尋會顯示不可用提示。內容修改後需重新建置才能驗證搜尋，不沿用上一次建置的索引。正式預覽使用 `pnpm build && pnpm preview`。

`e2e/search.spec.ts` 使用實際建置索引查詢 fixture 中的獨有測試詞，並檢查索引文字沒有排除欄位；英文 `*probe` 僅是虛構 fixture 的驗證標記。另以中文名稱與縣市查詢驗證中文搜尋。中文查詢由 Pagefind 斷詞，可能回傳部分詞彙相符的結果，並非逐字子字串搜尋。


## 本機草稿預覽

一般 `pnpm dev` 的首頁與景點頁包含本機草稿；新內容標示「新草稿」，同 id 覆蓋標示「修訂中」，並顯示尚未發布及全站本機預覽提示。這些標記與內容不進正式建置。新增、修改、刪除草稿後開發服務會重啟清除路由快取，重新整理即可查看。fixture 開發不合併私人草稿；全文搜尋仍以建置後索引為準。操作、錯誤與私人檔案邊界見[開發文件](development.md#第-05-票本機草稿與修訂預覽)。

## 列表縮圖

`/spot-thumbnails/<id>.webp` 與既有原圖路由共用景點選擇與 `readIllustration` 驗證。建置時只讀取當前正式／fixture 景點，開發預覽才允許所選草稿；不接受自訂圖片路徑、外部 URL 或尺寸參數。來源 PNG 與 YAML 不變，也不把縮圖寫入 `public/` 或內容資料夾。

使用固定版本 `sharp`（0.35.5，原已由 Astro 間接使用，本次宣告為直接依賴）將已驗證像素縮至 336×224 WebP、品質 76，採 3:2 置中裁切、保留來源透明度，且不保留中繼資料。列表仍以較小 CSS 尺寸顯示；快取版本包含縮圖樣式版本及來源圖 SHA-256，避免樣式更新後沿用舊留白縮圖。

正式輸出檢查逐份從已驗證原圖重新生成縮圖並比對完整位元組，只允許正式景點對應的固定路徑；缺檔、修改、額外 WebP 或草稿產物均會阻擋。既有原 PNG 的雜湊驗證不變。回復縮圖功能時移除列表引用、縮圖路由／轉換模組、直接依賴及相應驗證，原始核准內容與圖片保留。
