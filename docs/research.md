# 本機景點研究工具

內容工作入口是 [carltravel-research skill](../.claude/skills/carltravel-research/SKILL.md)。它負責旅遊來源閱讀或純官方資料研究、兩次人工決策和撰文；本機工具處理紀錄與可機械驗證的關卡，不自動抓網頁、不替 Carl 勾選或核准，也不開 PR。旅遊來源的讀取工具依當前執行環境提供，缺少工具須記錄不可用，再依 skill 前進。

## 建立、讀取與接續

在 repo 根目錄執行 `pnpm research --help` 查看完整用法。下列 `<…>` 都是需替換的參數；文字內容經本機檔案輸入，避免把原文或私人備註放進 shell 參數。

```sh
pnpm research init <YYYY-MM-DD> <網站或作者簡稱> <來源網址>
pnpm research attempt <來源-id> defuddle failed <本機失敗紀錄檔>
pnpm research attempt <來源-id> WebFetch unavailable <本機工具不可用紀錄檔>
pnpm research capture <來源-id> browser <本機完整原文檔>
```

`attempt` 的方法是 `defuddle`、`WebFetch`、`browser`；結果是 `failed` 或 `unavailable`。先前方法失敗或不可用才能前進。`capture` 也接受 `carl` 表示 Carl 提供全文。成功擷取直接使用 capture，會保存成功方式、日期與原文 SHA256，不需要再記一個失敗嘗試。

新來源配發 `<YYYYMMDD>-<slug>`，遇到本機研究目錄或正式／草稿 sources id 碰撞，依序加 `-2`、`-3`。同一來源供多個景點使用同一 id；接續研究直接使用原 id，不再次 init。init 不替代同一性判斷，也不以相同網址自動合併不同讀取批次。

`research/<來源-id>/` 初始包含：

| 檔案 | 責任 |
| --- | --- |
| `source.md` | 網址、讀取日期、工具嘗試、Carl 備註、不可讀決定及保留的讀取歷程 |
| `spots.md` | 四類拆分、Carl 勾選與日期、本批及待續 |
| `official-log.md` | 按事實記錄官方網址、查詢工具、結果、日期與不可讀項目 |
| `review.md` | 固定八項送審清單，未完成保留「待完成」 |
| `original.txt` | 由 capture 保存的完整原文，存在時不覆寫 |

固定 Markdown 標題供工具定位；保持其順序，不加第二個同名標題。私人備註可編輯「Carl 備註」，空項填「無」；備註中的二級標題須縮排成內容。其他查詢、勾選與送審項目以 Markdown 記錄，沒有另外的研究資料 schema。

研究根目錄及檔案不可用符號連結替代。新建私人目錄／檔案分別使用 0700／0600；不會搬移或刪除既有私人資料。原文取得證據先保存再寫原文，因此中途失敗會阻擋後續關卡，要求恢復資料，不會假裝從未取得。

## 純官方資料研究

Carl 只有景點主題、沒有旅遊網址時，先盤點候選並用 `research match` 比對，記錄四類拆分，等待 Carl 明確勾選。選定後每個景點使用獨立本機紀錄：

```sh
pnpm research init-official <YYYY-MM-DD> <spot-id> <notes-file>
```

`<notes-file>` 是含 Carl 原始備註的本機文字檔，沒有備註則內容為「無」。工具建立 `research/official/<spot-id>/record.md`、`official-log.md`、`review.md`；`record.md` 固定標題為「景點 id」「查證日期」「Carl 備註」「Carl 勾選日期」「Carl 勾選」，勾選欄初始為「未核准」，由代理核對真實決定後填入日期；「Carl 勾選」第一行填「已勾選」，後續填真實對話摘要。接續同 id 時讀取原紀錄，不重新初始化。官方查詢逐事實寫入 `official-log.md`，至少包含紀錄的查證日期及 HTTP(S) 官方網址；這僅驗證紀錄完整性，資料品質仍須人工審閱。完成檢查和實際預覽後填滿 `review.md` 八項。目錄及檔案沿用 0700／0600 和禁止 symlink 的私人資料邊界。

純官方資料的 `sources` 與 `authorNotes` 為空；官方頁只寫 `officialRefs`。沒有旅遊原文，也不使用 `init`、`attempt`、`capture` 或不可讀來源例外來製造來源證據。若草稿原本有旅遊來源，仍保留並按既有來源流程檢查。

大量純官方景點批次可將資料集快照、批次索引與逐筆狀態留在 `research/` 下的獨立私有目錄，每批最多十個候選，逐批交 Carl 勾選。只有已勾選項目能建立 `research/official/<spot-id>/` 紀錄及進入官方查證；不要把批次索引放進 `research/official/`，工具會將其中每個項目當成景點紀錄讀取。

若本輪要求先完成所有建頁資料再生成草稿，需等指定範圍內所有入選景點的官方查證完成，且待決項目已由 Carl 決定或明確略過，再逐筆生成純官方草稿。草稿保留 `sources: []`、`authorNotes: []`，不含插畫；逐筆預覽、完成送審清單後，整批交 Carl 審閱。未知、官方未公布與衝突按個別研究紀錄及內容 schema 表達，不以推測補值。

## 不可讀例外

三種方法均失敗／不可用，且 Carl 已在對話中明確接受後，將真實決定摘要存成研究目錄內的文字檔，再記錄：

```sh
pnpm research accept-unreadable <來源-id> <Carl接受日期> <本機對話決定摘要檔>
```

指令驗證嘗試順序與日期，拒絕覆寫決定；它只記錄已有決定，不能證明 Carl 確實說過該段話。skill 必須等到回覆，測試中的虛構決定也不構成真實授權。

缺少原文只有在來源標示不可讀、三種讀取嘗試都有失敗證據、Carl 有具日期的接受摘要、且從未取得原文時，才回報 `not_run_approved_unreadable`（未執行：原文無法讀取）。仍要檢查私人備註與其他來源。

任何取得紀錄或成功讀取嘗試，都代表原文曾存在：原文遺失時阻擋，即使後來把公開 `readable` 改成 false。空原文也阻擋。有原文就比對；關卡若發現人工恢復但未登記的原文，先將取得證據補入本機歷程。已登記的原文內容須符合保存雜湊，避免意外替換後錯用另一份文字；需要恢復時使用原保存內容。這是本機工作流程稽核，不是防止蓄意刪改所有紀錄的防竄改系統。

## 同一性與修訂

```sh
pnpm research match '<官方名稱>' '<地址>' [觀光署ID]
pnpm draft:copy <既有景點-id>
pnpm draft:diff <既有景點-id>
```

match 同時讀正式與草稿版本。名稱／地址只做 NFKC 與前後空白正規化，不作模糊地名推斷；觀光署 ID 需完整相同。唯一精確相符回傳 `match` 及建議 id，部分相符或不同精確訊號指向多個 id 回傳 `needs_decision`，沒有相符回傳 `new`。輸出含本機草稿的名稱與地址，只供本機決策，不是可公開報告。

工具建議不能代替第一次勾選。接續同 id 草稿須保留已做的工作；`draft:copy` 會複製已驗證的成對插畫 PNG，`draft:diff` 另列插畫雜湊差異。正式檔在內容核准與發布前不改，只更新受新來源影響且實際重查分節的日期。一般研究超過五個景點由 skill 建議分批；大量純官方批次每批最多十個。

## 共用重疊關卡

```sh
pnpm research check <草稿-id> [其他草稿-id …]
```

入口只接受指定草稿，先跑既有 schema；有旅遊來源的草稿須保留其 sources 參照，核准不可讀可作起始溯源。逐來源核對本機網址與讀取日期；缺紀錄、來源資訊不一致、遺失原文、未核准不可讀或 12 字命中都阻擋（exit 1）。有相符原文且沒命中回報 `pass`；核准不可讀的未執行狀態不偽報 pass。所有來源及備註均逐一處理。

- 每個涉及來源的原文，比對本批所有草稿（含純官方資料草稿）的非引文公開文字。遞迴遍歷已驗證資料，略過引用的 quotes 以及 id、ref、source、url 等參照／網址欄位；可見來源標題、作者、官方顯名仍在範圍內。長標題等合法重複也可能命中，須調整公開表達並交 Carl 審閱，不設自動放行名單。
- 每個涉及來源的私人備註，比對本批所有公開字串，包括引文、網址與參照中繼資料，防止把備註移到別的來源、景點或欄位略過檢查。
- 比對先做 Unicode NFKC，移除空白與 Unicode 標點，保留大小寫、符號與 Unicode code point。任意連續 12 字相同就阻擋，11 字不阻擋；分句標點及換行不會避開比對。不同欄位不拼接，避免製造跨欄位的相同片段。這是保守的機械檢查，不證明轉述品質或合法性。

純官方資料的逐景點結果列於 `officialOnly`：`{ id, original: 'not_applicable', notes: 'pass' | 'fail' }`。本機 `record.md` 必須有真實勾選，`official-log.md` 必須填有可追溯查詢，`review.md` 在送審前必須完成。官方資料備註比對本次**全部**指定草稿，不只對應 id；曾擷取而遺失的旅遊原文仍阻擋，不能藉清空 sources 或轉成純官方資料跳過。

終端 JSON 只含整體結果、逐來源與逐景點狀態及報告位置；命中文字、檔案與欄位診斷寫入 `research/overlap-report.md`。命令層錯誤寫入 `research/tool-error.md`，終端不列原文或 YAML 片段。報告每次更新，只代表這次指定草稿；修改文字後重跑，發布階段也要重跑。不要把私人報告附到 PR 或 CI artifact。

送審前啟動 `pnpm dev` 實際檢視，包括選填插畫及「AI 生成情境插畫，非實際展區」說明；把八項清單填入對應 `review.md`，空項寫「無」，再停下等待 Carl。純官方資料的原文結果表述為「未執行：純官方資料無旅遊原文」，備註檢查另報通過或失敗。暫存 app 的虛構情境測試會演練勾選、修訂差異、預覽與送審，並確認正式檔未變；它不取代真實來源的人工決策。

## 回復與限制

工具不新增套件、不呼叫網路、不修改正式內容、不執行 Git 發布。若程式回復到前版，保留 `research/` 與 `drafts/`；修正程式後可從原來源 id 接續。恢復原文時核對取得紀錄，不能刪除歷程或重新建立來源以規避失敗。

本票完成研究到送審，不包含完整私人索引外洩比對、發布 PR、CI／部署或真實來源上線驗收；這些由後續票交付。來源品質、官方查證是否充分、同一性待確認與內容取捨仍由 skill 和 Carl 的審閱負責。

研究紀錄更新會先完整寫入同目錄的私人暫存檔、同步檔案，再原子替換舊檔；失敗時保留舊紀錄，拒絕以符號連結作為目標。此機制避免寫入中斷清空紀錄，並非多位編輯者的並行合併或備份服務。
