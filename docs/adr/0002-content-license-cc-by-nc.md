# 景點內容採 CC BY-NC 4.0，程式碼採 MIT

CarlTravel 由本站撰寫的景點內容（`content/` 下的摘要、轉述、Agent 建議、親子清單等）採用 CC BY-NC 4.0；程式碼、schema 與 skill 採用 MIT，授權檔放在根目錄的 `LICENSE`。README 說明兩者如何劃分。

選 NC 而不選 CC BY 4.0，是刻意的取捨。CC BY 與政府資料開放授權條款相容，也是最開放的選項，但本站內容有很大一部分是部落客親子心得的轉述與整理。開放商業利用，等於讓內容農場可以合法地大量搬走「別人經驗的摘要」，這對原作者說不過去。NC 也與網站「個人、非營利」的定位一致。代價是 NC 的界線本來就模糊，實務上也不太可能追究，但它清楚表達了希望別人怎麼使用這些內容。保留所有權利同樣不打算追究，卻會擋掉非商業的轉載，所以不採用。

CC 授權不可撤回，已依 NC 釋出的版本永久有效。日後改為 CC BY 或收回授權，都追不回舊的副本，因此這個決定很難撤回。另外，景點文字主要由 Agent 撰寫、Carl 審閱，本站能主張的著作權範圍可能有限〔推論，未查證〕。授權的主要作用是表明使用意願。

授權只涵蓋本站撰寫的部分，以下三類不在範圍內：原作者引文（著作權屬原作者，依票 03 的合理引用處理）、官方事實（事實本身不受著作權保護，本站也不主張權利），以及政府開放資料。開放資料依政府資料開放授權條款第 1 版利用，該條款規定未依格式顯名就「視為自始未取得授權」，所以凡是有 `tourismId` 的景點，schema 都要求至少列出一筆 `kind: openData` 的官方出處，並由公開頁的「來源與官方出處」顯名。

**Falsified if:** 根目錄 `LICENSE` 不再是 MIT、`content/` 改用其他授權，或網站開始有商業收入（例如廣告或聯盟連結），使 NC 與自身的利用方式產生矛盾。
