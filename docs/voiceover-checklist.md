# VoiceOver 手動清單

自動化的 axe 與鍵盤測試測不到螢幕閱讀器實際念出什麼，所以下列項目由人在 macOS Safari 搭配 VoiceOver（Cmd+F5 開關）逐項走過。2026-10-17 的版本由 agent 撰寫，agent 無法執行 VoiceOver；尚未有人走過，結果欄待 Carl 填寫。

## 準備

1. `pnpm build:fixture && pnpm preview:fixture --port <空閒埠>`，Safari 開 `http://127.0.0.1:<埠>/`（fixture 共 62 筆，每頁 24 筆，共 3 頁）。
2. Safari 設定：進階，勾選「按 Tab 鍵可聚焦網頁上的每個項目」；VoiceOver 用 VO 鍵（Ctrl+Option）操作。
3. 各項在手機寬度（Safari 開發人員工具的響應式模式或 iPhone 上的 VoiceOver）重做一次「查看 N 筆結果」。

## 清單

| 項目 | 操作 | 預期 | 結果 |
| --- | --- | --- | --- |
| 換頁播報範圍文字 | 在 `/` 按分頁器「下一頁」 | 換頁後焦點落在範圍文字，念出「第 25–48 筆，共 62 筆」一類的文字；沒有另外念出第二組筆數 | |
| 篩選播報範圍文字 | 展開進階條件，選縣市「高雄市」 | 範圍文字更新後被念出新筆數，只念一次；選項不重複報筆數 | |
| 搜尋中的 `aria-busy` | 輸入「公園」或帶 `?query=公園` 進站 | 列表在載入／搜尋期間被標為忙碌，VoiceOver 不逐張念出過渡內容；結果出來後念出範圍文字 | |
| 卡片一個 Tab 停點 | 在列表用 Tab 前進 | 每張卡片只停一次，名稱是景點名稱（例如「川禾藝文中心 1866 號（虛構）」），不是「閱讀更多」；縣市、類型與摘要用 VO 方向鍵可讀到 | |
| 摺疊列摘要與狀態 | 開任一景點頁，用 VO 方向鍵走過摺疊列 | 每列念出章節名稱、提要（例如「已知 3／5 項」「有衝突」）與展開／收合狀態；「尚未整理」的列不是按鈕、不能展開 | |
| 錨點展開 | 從卡片的列或帶 `#章節` 的網址進入景點頁 | 目標章節展開，焦點在它的摘要上，念出章節名稱與已展開 | |
| 「查看 N 筆結果」 | 手機寬度，展開進階條件、改選項後按「查看 N 筆結果」 | 篩選區收合，焦點移到範圍文字並念出新範圍；改選項本身不捲動、不搶焦點 | |
| 返回列表連結 | 從 `/page/2/` 點進景點，再用頁首的「← 回到剛才的列表」 | 連結文字念出「回到剛才的列表」；按下回到第 2 頁，捲動位置與原來的連結焦點還原。直接開景點頁時文字為「← 景點列表」 | |
| 無結果恢復 | 選出 0 筆的組合 | 範圍文字念出無結果；逐項移除條件的連結各自念出筆數（例如「移除縣市，剩 N 筆」） | |

## 記錄

走過後在驗收文件新增一節（日期、macOS 與 Safari 版本、每項通過或問題），把發現的問題開成票；本清單只收規則，不放螢幕閱讀器的錄音或截圖。
