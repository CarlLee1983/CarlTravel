### 補充決策與例外

1. **同 id 修訂隔離**（補充品質關卡）：正式建置只讀 `content/`；開發預覽才載入 `drafts/` 並讓同 id 草稿優先。尚未發布的 id 不得出現在正式站、sitemap 或 Pagefind。修訂草稿與正式內容同 id 時，正式輸出保留原已發布版本；以修訂專有文字驗證新內容未提前進入頁面或搜尋索引，不能只用 id 判斷。用虛構 fixture 覆蓋兩種情況。
2. **原文無法讀取仍可建立景點**（修正研究流程的收錄條件）：三種讀取方法都失敗後，Carl 明確接受 `readable: false`，且景點仍符合台灣固定景點及有官方資料可查證的範圍時，可依官方資料建立景點。此例外不要求取得作者造訪證據，不撰寫該來源的原作者心得或引文，公開標示原文無法讀取。Carl 備註仍只作查證線索。此路徑的 `sources[]` 條目作為景點研究的起始來源，並在公開來源清單呈現不可讀狀態，視為有效使用，不要求捏造心得或周邊安排來引用它；品質關卡對 `readable: false` 的來源接受此溯源用途，本機發布關卡另外驗證 Carl 的核准證據。其他未被使用的來源仍報錯。
3. **缺少比對原文**（補充研究與發布關卡）：核准為無法讀取的來源，原文照抄比對記為「未執行：原文無法讀取」，不宣稱通過；私人備註比對及其他關卡照常執行。來源原本讀取成功卻遺失 `original.txt` 時，阻止開 PR，補回資料再檢查。多來源景點逐一列出狀態，不能因其中一份不可讀就略過其他來源。已核准不可讀來源若仍有本機原文可供比對，應執行比對。
   此例外的證據留在本機 `research/<來源 id>/source.md`：逐一記錄讀取嘗試與結果，以及 Carl 接受不可讀狀態的日期和對話決定摘要。發布關卡須核對該證據；只有 `readable: false`、卻沒有 Carl 核准紀錄，或把原本可讀但遺失原文改標不可讀，均阻擋開 PR，不自動套用例外。
4. **公開檢查報告**：PR 只附檢查狀態與可公開摘要，不附私人備註、原文全文或命中的私人文字。詳細診斷留在本機研究紀錄與對話。

### 實作邊界與文件責任

實作時建立 `docs/architecture.md`，說明下列邊界、資料流及對應驗證入口：

- `content/spots/<id>/spot.yaml` 是正式資料，與本機 `drafts/spots/<id>/spot.yaml` 共用 schema；草稿狀態由目錄決定。正式 loader 與開發草稿覆蓋行為分開，模式切換不得殘留草稿快取。
- `research/<來源 id>/` 保存原文、私人備註與研究紀錄，只由本機流程和檢查讀取。`drafts/`、`research/` 均不進 Git、網站資產或 CI artifact。
- schema 擁有資料結構及參照驗證；內容檢查擁有跨檔與輸出驗證；頁面只渲染已驗證資料。搜尋索引與 sitemap 依頁面決策採白名單。
- `.claude/skills/carltravel-research/` 擁有讀取、查證、草稿與送審流程；`.claude/skills/carltravel-publish/` 擁有審閱通過後的本機檢查及 PR 準備。兩者提交公開 repo，內文只寫規則。
- PR CI 與部署工作流程共用 verify；正式部署前以正式內容重建並再查輸出。部署驗證與 fixture 建置分離，測試資料不得部署。
- Carl 的內容審閱、PR 合入與自動部署是不同階段：合入代表發布核准；部署成功並確認公開站，才算完成上線驗收。失敗時保留未完成狀態，不把已合入當作已上線。

實作時將以下兩節放進 `AGENTS.md`；本票中的文字是待實作規格，不在本輪建立生效中的根目錄指引：

```markdown
## 代理權限

- 草稿與研究紀錄留在本機的 `drafts/`、`research/`，遵循 docs/architecture.md 的資料邊界。
- Carl 在對話中審閱通過指定草稿後，依 carltravel-publish 執行本機關卡，將核准內容準備到工作分支，提交、推送該分支並開 draft PR。只有核准的內容與可公開檢查摘要能進 PR。
- CI 全綠且修改完成後才將 PR 轉為 ready。後續再修改時重新跑受影響關卡；已合入則從最新 main 另開分支與 PR。
- Agent 不推送 main、不合入 PR、不執行正式部署或正式回滾。Carl 合入表示發布核准，由既定自動部署流程上線；Agent 可讀取部署結果並驗證公開頁面。

## 內容製作入口

- 收到旅遊來源、建立景點草稿或補充既有景點時，使用 `.claude/skills/carltravel-research/`，依 CONTEXT.md 的名詞與 skill 的送審節點操作。
- Carl 審閱通過並準備發布指定草稿時，使用 `.claude/skills/carltravel-publish/`。研究流程不直接修改正式內容或發布。
```

### 實作順序與完成條件

1. **骨架與品質關卡**：建立 Astro 靜態網站、schema、四種頁面、搜尋篩選、授權宣告與驗證指令。依 D 原型實作，以 fixture 通過正反案例及版面檢查。零正式景點時可完成開發與測試；正式部署仍要求至少一個審閱通過的景點。
2. **研究與發布 skills**：補齊兩個 skill 及本機關卡。用虛構資料證明送審節點、不可讀例外與失敗阻擋行為；只有明確審閱通過的草稿能進 PR。
3. **基礎設施設定**：沿用已存在的公開 repo `CarlLee1983/CarlTravel`（2026-10-15 以 gh 確認），不另建 repo；完成 Cloudflare Workers Static Assets、自動部署設定及 `carltravel.gravito.dev` 網域設定。設定與發布依實作階段的授權執行；本規劃不授權操作帳號或部署。
4. **真實流程驗收**：Carl 提供符合收錄條件的真實網址，走完研究 → 本機草稿 → 本機預覽與審閱 → PR → Carl 合入 → 自動部署 → 公開頁驗證。若提供的網址不符條件，記錄拒絕原因，另選合格網址完成發布路徑；拒絕處理本身不算通過完整上線驗收。

### 驗收矩陣

| 項目 | 可觀察的通過條件 |
| --- | --- |
| 真實內容流程 | 至少一個真實景點完成上述全流程，保留可公開的 PR、部署結果與公開頁連結；私人研究證據留本機 |
| 草稿與修訂隔離 | 開發可預覽新草稿與同 id 修訂並標示；正式頁面及 Pagefind 無草稿專有文字，新草稿 id 不在頁面、sitemap、搜尋中；同 id 已發布頁仍是正式版本；開發後再正式建置亦成立 |
| 本機照抄與私人備註 | 虛構的 12 字重疊案例使關卡失敗、停止開 PR；有效內容通過。不可讀與原文遺失依補充決策分別記未執行或阻擋；另測未核准的 `readable: false` 及遺失原文後改標不可讀都會阻擋 |
| 結構、參照與授權 | 無效 schema、缺出處、無效 ref、引文超限、缺開放資料顯名及圖片等品質關卡案例失敗；有效 fixture 通過。政府資料定位所需顯名、核准不可讀來源的溯源條目均視為有效使用，不被未引用條目檢查誤擋；官方資料建立的景點 fixture 不含心得或引文仍可通過 |
| 公開輸出與 Git | 本機私人資料不進追蹤檔案、PR、正式站或 artifact；以虛構標記驗證外洩檢查會失敗，不使用真實私人內容作 CI fixture |
| 頁面與搜尋 | 首頁、景點頁、關於頁與 404 存在；搜尋只收既定景點欄位；四種篩選、無結果與清除條件可用；sitemap 僅含首頁、正式景點與關於頁 |
| 狀態呈現 | 官方未公布、衝突雙方出處、原文無法讀取、超過 12 個月與有／無／未知都有可讀文字；過期只警告，不阻擋發布 |
| 無障礙與版面 | 四種頁面以 fixture 跑 axe 零違規；360、390、430、1366、1920 像素無頁面水平捲動；景點章節目錄、搜尋與篩選可用鍵盤操作 |
| PR 與正式部署 | 共用 verify 通過 format、astro check、建置、內容檢查、unit、e2e／axe、wrangler dry-run；部署前正式重建並檢查，至少一個正式景點；公開網域內容與核准版本相符 |
