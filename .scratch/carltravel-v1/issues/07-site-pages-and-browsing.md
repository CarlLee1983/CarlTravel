# 網站頁面範圍與瀏覽方式

Type: grilling
Status: resolved
Assignee: Carl
Blocked by: 04

## Question

v1 公開網站有哪些頁面，讀者如何找到景點？

- 頁面清單：首頁、景點頁、縣市列表、主題標籤頁、搜尋、關於／免責聲明、404，哪些是 v1 必要的。
- 網址結構，例如 `/spots/<id>/`、`/regions/<縣市>/`。
- 主題標籤的值域：室內／戶外、雨天備案、停留時間，誰可以新增標籤。建議年齡已依票 04 改成獨立的範圍欄位 `ageRange`，不是標籤，這裡只決定如何用它篩選。
- Pagefind 要索引哪些欄位，搜尋結果是否要提供縣市與標籤篩選。
- 免責聲明的內容：資訊以官方為準、查證日期的意義、親子設施資訊僅供參考。
- 補充過的景點，公開頁是否顯示「更新紀錄」；若要顯示，資料要從 Git 歷史取得，還是另設欄位。依票 05，補充景點時只會更新重查過的分節的 `checkedAt`。
- 景點數量很少時（v1 上線時可能只有一個），首頁與列表頁要怎麼呈現才不顯得空洞。

## Answer

以下由 Carl 於 2026-10-15 確認。

### 頁面與網址

- v1 只做四種頁面：首頁（`/`）、景點頁（`/spots/<id>/`）、關於頁（`/about/`）、404。縣市列表頁與主題標籤頁不做，景點數量變多後再議。
- 景點發布後 id 不再變更，因為 id 就是網址。v1 不做轉址；真的需要更名時，由 Carl 決定是否接受舊網址失效。`carltravel-research` 補充既有景點時沿用原 id。
- sitemap 白名單只收首頁、每個景點頁與關於頁，404 不收。這四種頁面就是「自動品質檢查與發布關卡」中 axe 與水平捲動檢查要涵蓋的頁面種類。

### 分類欄位（修正票 04）

- 頂層的 `tags[]` 拆成兩個封閉列舉欄位：`kind`（公園、博物館、農場、步道、老街、觀光工廠、動物園／水族館、其他）與 `setting`（室內、戶外、室內外皆有）。
- 「雨天備案」沿用 `familyChecklist` 的項目，不另設標籤。「停留時間」屬於 Agent 建議，v1 不做成可篩選欄位。
- 新增列舉值的流程：Agent 在送審清單中提議，Carl 以 PR 修改 schema。
- 新增必填欄位 `summary`：一句 30 字以內的摘要，由 Agent 撰寫，屬於轉述，不得照抄來源。首頁卡片與 Pagefind 都使用這個欄位。

### 首頁、搜尋與篩選

- 首頁開頭放一段簡短介紹，說明網站是什麼、三類資訊如何區分、內容經審閱後才發布，接著列出全部景點。卡片顯示名稱、縣市與行政區、`kind`、年齡範圍與 `summary`。
- 預設排序：依 `county` 列舉順序（由北到南），同一縣市內依名稱排序。不提供「最新」排序。
- 搜尋框一律顯示。篩選只列出至少有一個景點的值，不另做「景點少時隱藏篩選」的條件式畫面。
- Pagefind 只索引景點頁，索引的欄位有：名稱（權重最高）、縣市與行政區、`summary`、原作者心得的轉述摘要、Agent 建議、「跟孩子一起看」。官方資訊的數值、引文、來源清單與周邊安排不進索引。
- 篩選維度為縣市、`kind`、`setting`、年齡帶。年齡帶在 build 時由 `ageRange` 換算，分為 0–2 歲、3–6 歲、7–12 歲、13 歲以上，與範圍重疊的年齡帶都會掛上；`ageRange` 是 unknown 時，掛「年齡未標示」。

### 景點頁

分節順序由上到下為：

1. 標頭：名稱、縣市與行政區、`kind`、`setting`、年齡範圍、`summary`
2. 親子清單
3. 開放時間與費用
4. 交通與停車（含 Google Maps URLs 與 OSM 連結）
5. 設施（選填）
6. 跟孩子一起看（選填）
7. 原作者心得
8. Agent 建議
9. 周邊安排
10. 來源與官方出處
11. 免責聲明短版，連到關於頁

這張票只決定順序，樣式屬於[視覺方向](10-visual-direction.md)。

### 免責聲明與更新紀錄

- 完整版放在關於頁，涵蓋四點：
  - 實際資訊以官方公告為準，出發前請再確認。
  - 「查證日期」指 Agent 在該日查看官方出處時的內容，不保證之後仍然有效。
  - 親子與無障礙設施資訊僅供參考；「未知」代表官方未公布，不代表沒有這項設施。
  - 原作者心得只代表原作者本人的看法。
- 授權宣告的位置由[網站內容的授權宣告](09-site-content-license.md)決定，關於頁先預留。
- v1 公開頁不顯示更新紀錄。各分節的 `checkedAt` 與各來源的 `readAt` 已足以讓讀者看出各部分的查證時間。
